# CoachChris — context to reuse for a new app

**What it is.** A single-user training cockpit. It reads Garmin data (sleep, heart-rate variability, activities, weight) and the Campus Coach training plan through MCP servers. It caches everything in Cosmos and shows it in a mobile-friendly React app. It can write back (validate a session in Campus, send a workout to the watch, annotate an activity), always after a preview and an explicit confirmation. Budget target: about 7 €/month.

Details: [ARCHITECTURE.md](../ARCHITECTURE.md) (how it is built) and [DECISIONS.md](../DECISIONS.md) (why, D1…D147).

## Architecture

```
React SPA (Static Web Apps Free) ──MSAL token──▶ BFF (Fastify, Container Apps, Easy Auth)
                                                  ├─▶ Cosmos NoSQL (free tier): cache + user state
                                                  ├─▶ MCP Garmin  (Container App, internal, 0–1 replica)
                                                  └─▶ MCP Campus  (Container App, internal, 0–1 replica)
Sync job (Container Apps Job, daily cron) ─── same image as the BFF
Tokens for external services ─── Azure Files share mounted into the MCP containers
```

## Stack

- **Monorepo, npm workspaces:**
  - `domain/`: pure TypeScript business rules, with no input/output (I/O), fully unit-tested;
  - `server/`: Fastify + zod BFF (sync, read models, write actions);
  - `web/`: Vite + React 19 + Tailwind 4.
- **Python** (FastMCP, `uv`) for a custom MCP server (`mcp/campus`). The Garmin MCP comes from an existing project, built here from a Dockerfile (`mcp/garmin`).
- **Infra:** Bicep (`infra/main.bicep` at subscription level for the resource group and budget, `infra/app.bicep` for the app, `infra/bootstrap.ps1` for the one-off setup).
- **CI/CD:** GitHub Actions. `ci.yml` runs lint, typecheck and tests. `deploy.yml` builds images to GHCR (public), deploys the infra and deploys the static web app. GitHub authenticates to Azure with OIDC, so no secret is stored.

## Reusable as is (the "platform")

| Building block | Notes |
| --- | --- |
| **Auth** | Entra app registration (only assigned users allowed). MSAL redirect in the SPA. Easy Auth on the Container App. The BFF re-checks the user's object ID in `x-ms-client-principal-id`. |
| **Silent-renewal pitfall** | Entra forces a new sign-in for an SPA every 24 h. MSAL first tries a hidden iframe; when the browser blocks it, the error is `timed_out`, not "interaction required". Handle `BrowserAuthError` → `acquireTokenRedirect` (D142). |
| **Cosmos access** | Managed identity + data-plane RBAC, no keys. Free tier: only one per subscription, and it must be set at creation. Pick the credential explicitly: `DefaultAzureCredential` cost about 24 s on cold start (D114). |
| **Cold start** | Scale to zero is cheap but takes about 25–30 s to wake. Mitigations: the front pings `/api/health` on load, a clear loading message, and an optional KEDA cron rule keeping one replica warm during the day (about 2–3 €/month, D129). |
| **Write protocol** | `POST /actions/preview` → HMAC-signed token (5 min, single use, contains the exact calls) → `POST /actions/confirm`. Every tool response is checked. Every write is logged (D123). |
| **Sync pattern** | Read endpoints serve the cache immediately, then sync in the background. Retries with backoff, never on an expired token. A daily job on a UTC cron. |
| **Installable app (PWA)** | Manifest, icons generated by a script (`web/scripts/icons.mjs`), `viewport-fit=cover` + safe areas, touch targets ≥ 40 px, inputs at 16 px (otherwise iOS zooms) (D140). |
| **Costs** | Subscription budget with email alerts at 50 / 80 / 100 %. A budget only warns; it doesn't block. It lives under the subscription's Cost Management → Budgets, not in the resource group. |
| **Theme** | Colour tokens on `:root`, light and dark, Auto / Sombre / Clair choice stored per device (D128). |

## Specific to this app (don't copy as is)

- Garmin and Campus MCP servers and their token renewal (`reauth.ps1` on the PC, browser bookmark on the phone).
- Training logic: matching sessions to activities, step-by-step comparison, placement rules, volume reference, mobility routines.
- **Single user** throughout: one dataset with no per-user partition, one set of external tokens. To serve several people, either deploy one copy per person (cheap) or redesign for real multi-user (data partition, onboarding, GDPR for health data).

## Working conventions that paid off

- Never invent missing data: absent values show as "unavailable".
- Every decision is recorded in `DECISIONS.md`; `ARCHITECTURE.md` is kept up to date.
- Business rules live in `domain/`, tested on real data.
- Local dev uses the same Cosmos as production, without auth. Careful: a write in local dev changes real data.
- Windows gotchas: PowerShell 5.1 strips quotes and adds a BOM; use Node scripts instead of sed/perl for edits with special characters.
